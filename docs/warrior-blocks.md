# Warrior block catalog

Generated by `node scripts/blocks.js catalog`. Edit definitions in `tools/blocks/catalog.js`.

Inventory: 147 local source files, 35 public references (35 inspected). See [source map](block-sources.json) for hashes, line ranges, dependencies, family hints and failures.

## Executable grammar

Opening (none / timed bomber / timed B-scan) → transfer (in place / relocation) → terminal clear (DAT / short stun then DAT / full stun then DAT). Both directions are supported. Every recipe assembles with symbolic labels, measures its size, and passes a full solo behavioral gate before evolution can evaluate it. P-space and torus code are inventoried but cannot enter this ring grammar.

The '88 implementation uses explicit forward pointer increments, legal DAT operands, CMP spelling where needed and END entry. It is not a modifier-stripped '94 conversion. Source section discovery is heuristic; only the seven explicit implementations below are selectable.

## Blocks

| Block | Purpose | Admission | Parameters / extraction requirements |
|---|---|---|---|
| opening-none | Skip attack and transfer immediately. | Executable; behavioral gate required | none |
| opening-bomber | Bounded stride DAT bombing with own-image guard. | Executable; behavioral gate required | STEP, WAIT |
| opening-bscan | B-field scan with bounded SPL bombing and timer. | Executable; behavioral gate required | STEP, WAIT |
| relocate-copy | Backward copy of a self-contained payload; jump once into the copy. | Executable; behavioral gate required | HOP |
| enter-in-place | Enter the payload in the original image. | Executable; behavioral gate required | none |
| clear-dat | Repeated bounded DAT passes excluding the complete active payload. | Executable; behavioral gate required | BACKWARD |
| clear-stun-dat | Short or full SPL pass, then reset pointer for repeated DAT passes. | Executable; behavioral gate required | BACKWARD, PHASE, STUN |
| marker-trigger | Change phase when a remote marker is damaged, with timer fallback. | Documented candidate | Existing Molting verifier covers the whole template; extract sensor placement and marker ownership contracts. |
| compare-scan | Compare two cells to detect an opponent. | Documented candidate | Preserve scan offsets, skip/jump coupling, self-scan exclusion and attack handoff. |
| quickscan | Unrolled early probes followed by a targeting decoder. | Documented candidate | Tables, decoder constants and probe order form one linked section; measure instruction cost. |
| one-shot | Switch from scanning to a clear on the first hit. | Documented candidate | Scanner and clear must agree on pointer interpretation and direction. |
| vampire-fang | Place a jump that transfers opponent processes to a pit. | Documented candidate | Fang and pit are linked by destination-relative arithmetic; copying a fang alone changes its target. |
| paper-copy | Copy a body and launch it elsewhere. | Documented candidate | Per-copy counters, initialization and parent/child scheduling; safe overlap must be tested. |
| silk-launch | SPL/MOV replication using cooperating processes. | Documented candidate | Process count and scheduling are part of the interface; incompatible with single-process clear counters. |
| imp-spiral | Launch mutually supporting imp processes. | Documented candidate | Core-relative stride congruences, launch order and process budget; impring fails solo on 94x. |
| decrement-gate | Damage advancing imps or streams through a guarded cell. | Documented candidate | Gate location and timing must match the clear; no blanket anti-imp guarantee. |
| pspace-selector | Select behavior using persistent round outcomes. | Documented candidate | Requires P-space-enabled profile, cell ownership and multi-round tests. Forbidden under 88, lp, 94nop and 94x. |
| torus-turn | Turn and sweep across axes. | Documented candidate | TRN extension, heading on entry/exit, dimension-specific bounds; not ring code. |
| torus-replicate | Distribute copies through a volume. | Documented candidate | Vector offsets, heading inheritance, copy overlap and geometry-specific cycle coverage. |
| anti-clear-relocation | Watch a clear front and jump behind it. | Documented candidate | Sensor direction, latency and safe landing; preserve negative hybrid evidence in prototypes README. |

Full contracts and source references: [machine catalog](block-catalog.json). Behavioral evidence belongs to a recipe, settings and source hash, not to a strategy name. Benchmark evidence is separate from correctness.

## Workflow

1. Rebuild inventory: `node scripts/blocks.js inventory`. Add `--public` to refresh the 35 public archive references. Downloads stay in ignored `imported/block-sources/`; metadata is tracked. Failed fetches remain visible.
2. Generate documentation: `node scripts/blocks.js catalog`.
3. Make a legal, behavior-checked warrior: `node scripts/blocks.js build --rules 94x --out evolved/blocks/sample`. Writes Redcode, recipe/contract evidence and a JavaScript generator usable with the existing tuner.
4. Evolve choices and parameters: `node scripts/evolve-blocks.js --rules 94x --out evolved/block-search`. Saved recipes include source hashes, parents and emitted section boundaries.
5. Parameter tuning: `node cli/zorewars.js tune evolved/blocks/sample.js --rules 94x --length 50 --candidates 12`. Tuner output must pass `blocks.js verify` with its saved parameter object before promotion; the ordinary tuner does not call the block gate.
6. Re-check a saved recipe: `node scripts/blocks.js verify --recipe evolved/blocks/sample.recipe.json`. Changing JSON parameters recompiles and rechecks; do not label hand-edited Redcode as verified by the old receipt.

## Adding a family

Record provenance and source hash, find symbolic dependencies, define process/memory/entry/exit contracts, then implement an emitter and adversarial behavior tests. Demonstrate actual copy, attack and phase behavior at wrapping placements before admission. Keep old recipes reproducible by preserving their parameters, emitted source and version. Public code is reference material; an unknown license is not permission to redistribute it. Neither an inferred label boundary nor a successful assembly promotes a source into the grammar.

Research foundation: [annotated ICWS '94 draft](https://corewars.org/docs/94spec.html), local engine semantics, and archive URLs in the source map. The draft is historical; extensions are explicitly identified.
