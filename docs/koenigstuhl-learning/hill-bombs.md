# Bombs used by our hill opponents

A bomb is an instruction a warrior drops into shared core to disrupt another warrior. In `MOV.I bomb, @ptr`, the MOV delivers the bomb. The instruction at `bomb` determines what gets installed. The overwrite happens immediately. If a process later executes the bomb, the offsets are relative to its new location and the process still uses its original warrior’s queue. A hit on a pointer or an instruction read as data can also matter before anyone executes it. [ZoreWars VM](../../src/engine/vm.js#L453) · [ICWS ’94 draft](https://corewars.org/docs/94spec.html)

## What each bomb does

| Payload | Effect when a process reaches it | Opponent example |
| --- | --- | --- |
| **Plain DAT** `DAT.F #0,#0` | Kills the executing process. A warrior with other queued processes keeps fighting. Sample Bomber starts with `DAT #5333,#5333`, which has the same effect when executed. | [Sample Bomber](../../imported/sal-survey-20261107/source-94/HILL32/samplebomber.red#L8) |
| **DAT with a side effect** `DAT.F <2667,$46` | Decrements the B-field 2,667 cells ahead, then kills the executing process. If that remote cell holds a direct-destination three-point imp with stride 2,667, its stride changes to 2,666. Azathoth instead uses `DAT }sstep,>1` to increment two pointer fields before death. | [Elven King](../../imported/sal-survey-20261107/source-94/HILL32/elvenking.red#L40) · [Azathoth](../../imported/sal-survey-20261107/source-94/HILL32/azathoth.red#L26) |
| **MOV that overwrites the next instruction** `MOV.I $4021,$1` | Reads the cell 4,021 ahead, copies it over the next instruction, then queues that next cell. An empty source turns the next step into a DAT death. Occupied core can make the victim execute some other instruction. | [Myrmidon](../../imported/sal-survey-20261107/source-94/HILL32/myrmidon.red#L26) |
| **MOV that turns a process into an imp** `MOV.I #1010,$1` | With explicit `.I`, immediate A selects the whole executing instruction. The victim copies the bomb one cell ahead and follows it, repeatedly replacing its own work with a one-step imp. The 1,010 is carried in the A-field. The B-field of 1 sets the copy distance. | [Recount](../../imported/sal-survey-20261107/source-94/HILL32/recount.red#L16) |
| **MOV that uses the victim’s next cell as a pointer** `MOV 0,<1` | Decrements the next cell’s B-field and uses it to decide where to copy itself. If the original B-field was 0, it copies over itself. If it was 1, it copies over the next cell. Either way, execution advances to the next cell. | [The Next Step ’88](../../imported/sal-survey-20261107/source-odd/HILL32/nextstep88.red#L38) |
| **JMP that stalls** `JMP #1,#1` | Immediate A resolves to the current cell, so the process stays there. Each trip through the loop uses one of the victim’s turns. The LP Destroyer follows with a DAT clear. Kenshin’s `JMP #0,}0` also loops in place and increments its own A-field on every execution. | [The LP Destroyer](../../imported/strategy-trends/lp-6.red#L57) · [Kenshin X test 112](../../imported/sal-survey-20261107/source-94/HILL32/kenshinX112.red#L24) |
| **JMP that captures** | A vampire drops a JMP called a *fang* whose offset leads back to its trap. Forgotten Lore II adjusts a B-indirect fang as it moves the drop point. Elemental Dust 2 uses a direct jump. Its drop offset and jump offset change in opposite directions so the two offsets still add up to the trap location. The captured process can then spend its turns splitting or clearing core for the vampire. | [Forgotten Lore II](../../imported/sal-survey-20261107/source-94/HILL32/lore2.red#L19) · [Elemental Dust 2](../../imported/strategy-trends/88-9.red#L43) |
| **SPL that stuns** `SPL #-3147,-3147` | The parent queues the next cell and the child queues the bomb again. A carpet of these instructions fills the victim’s queue with more SPL work, up to its process cap. Excalibur lays a 16-cell SPL wipe and can follow it with a DAT clear. | [Excalibur](../../imported/sal-survey-20261107/source-94/HILL32/excalibur.red#L56) · [VM queue order](../../src/engine/vm.js#L570) |
| **DJN that stalls and corrupts** `DJN.F #1,$1` | Decrements both numeric fields of the next cell and jumps back to itself while either field is nonzero after the decrement. Starting from two zero fields, the first execution changes both to 7,999 in an 8,000-cell core. A DJN stream can also damage remote fields directly as the attacker runs its own DJN. | [Forgotten Lore II](../../imported/sal-survey-20261107/source-94/HILL32/lore2.red#L84) · [VM decrement and branch](../../src/engine/vm.js#L543) |

**Field-only bombs** can damage a warrior without installing a new opcode. Death by Numbers uses `MOV.F bomb,>ptr` with a `NOP.F 1,1` template. The victim’s opcode, modifier and addressing modes survive, while both numeric fields become 1. Frogskin 4 uses a full copy of `NOP <0,<0`. A process that executes it falls through after decrementing the bomb’s own B-field twice. [Death by Numbers](../../imported/sal-survey-20261107/source-94/HILL32/deathbyn.red#L13) · [Frogskin 4](../../imported/sal-survey-20261107/source-94/HILL32/frogskin4.red#L12)

**P-space and arithmetic** add two cases. Fire and Ice II drops `STP.AB >0,#0` after an SPL wipe on the X hill. A victim process that executes it writes into its own warrior’s P-space. The first execution of a fresh copy clears slot 1. A zero-divisor payload such as `DIV.AB #0,$1` also kills on execution. I verified that case by planting the instruction in the VM. The sampled DIVs include ordinary copied paper code such as DivideAndConquerV2Quicker’s divide-by-two pointer update. [Fire and Ice II](../../imported/strategy-trends/94x-2.red#L103) · [DivideAndConquerV2Quicker](../../imported/sal-survey-20261107/source-94/HILL32/DivideAndConcuerV2Quicker.red#L19) · [VM arithmetic](../../src/engine/vm.js#L510)

## What showed up in our 94nop fields

I ran three bouts per archived opponent against Contender 50 direct, Silk and Scout. That covered 49 available opponents from the first 50 published ranks and all 408 opponents from the saved length-50 benchmark, for 1,371 bouts. Rank 15 was absent from the frozen top field. Each count is the number of distinct opponents that copied the opcode into a cell with `MOV.I` and subsequently had the other warrior execute that cell with the copy still recorded as its last write. Ordinary paper copies and imp seeding can qualify, so the counts measure foreign execution rather than the prevalence of deliberate bombs. Field-only hits, untouched traps and bombs overwritten before execution are outside this measurement. [Frozen 94nop images](../../evolved/l2-fullrr-20261101/programs.json) · [Length-50 field](contender-50/benchmark/field.json)

The source-confirmed replays below load the hill opponent at 0. For the full sample, target order is direct, Silk, Scout, numbered 0 through 2. The target’s base is `100 + (publishedRank * 1741 + targetIndex * 2297) % 7801`. The first mover is `(publishedRank + targetIndex) % 2`, where 0 means the hill opponent. The VM uses an 8,000-cell core and 80,000 cycles. [Contender 50 direct](contender-50/benchmark/direct.red) · [Silk](../../warriors/silk.red) · [Scout](../../warriors/scanner.red)

- **Myrmidon vs Scout**, base 3,523, cycle 910. The MOV at 3,526 read empty cell 7,547 and overwrote Scout’s `SLT` at 3,527 with that DAT. Scout’s next queued address was 3,527.
- **Recount vs Contender 50 direct**, base 6,129, cycle 626. The MOV at 661 overwrote our `MOV.I #0,$1143` at 662 with `MOV.I #1010,$1`, then queued 662.
- **Forgotten Lore II vs Contender 50 direct**, base 167, cycle 566. The JMP at 3,588 read the pointer at 219 and queued the trap’s `SPL` at 95.
- **Excalibur vs Silk**, base 4,205, cycle 426. The SPL at 1,539 queued both the next cell at 1,540 and a new process back at 1,539.
- **Elven King vs Silk**, base 5,310, cycle 3,850. The DAT at 5,309 killed the executing process and changed Silk’s MOV at 7,976 from `MOV.I >-2, }-1` to `MOV.I >-2, }-2`. A separate planted check confirmed the same decrement changes a 2,667-stride imp to 2,666. [Earlier anti-imp traces](anti-imp-bomb.md#friendly-fire-and-phase-checks)

A MOV bomb can make a loss look self-inflicted in a battle report. When the victim copies a DAT onto its own next cell, the VM records the victim as the last writer and reports an `ownCode` death. Check the preceding instructions in `trace` for the enemy’s MOV or JMP that started the sequence. [VM death attribution](../../src/engine/vm.js#L275)
